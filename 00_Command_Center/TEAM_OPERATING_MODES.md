# 团队运行模式

共同原则：AI 扩大搜索空间，孩子做价值判断，制作负责人承担范围与交付责任；每次贡献都留证据而不夸大。

## 模式 A：女儿在线

| 角色 | 现场动作 | 证据 |
|---|---|---|
| 芊芊 | 判断规则是否想再玩一次；提出反常识变化 | 原话、草图、选择时间 |
| 萱萱 | 判断画面情绪与角色吸引力；挑视觉方向 | 原话、草图、选图记录 |
| 制作负责人 | 主持、范围裁剪、唯一拍板、验收 | 决策导出、GAME_MAP、测试记录 |
| ChatGPT 主窗口 | 四专家互相质疑、生成验证问题 | AI usage log 与上下文摘要 |
| Codex 工程窗口 | 按地图/契约一次实现一个模块 | 文件清单、diff、测试结果 |

- [ ] 每 30 分钟让孩子做一次二选一或三选一价值判断。
- [ ] AI 产出不得直接署名给孩子；孩子修改了什么要写清。

## 模式 B：女儿卡壳／暂时离线

- [ ] 主持人用 [`CHILD_CREATIVE_SCRIPT.md`](CHILD_CREATIVE_SCRIPT.md) 的卡壳脚本，不连续追问。
- [ ] AI 只生成 3 个明显不同的可选项和各自代价，不做最终选择。
- [ ] 制作负责人先做可逆的技术骨架，不锁美术和叙事价值判断。
- [ ] 建立“待孩子判断”队列：核心动作、情绪、角色、记忆画面，每项最多 3 选 1。
- [ ] 孩子恢复在线后补做判断；原方案与修改结果同时入日志。

## 真实贡献记录

- [ ] 使用 [`AI_USAGE_LOG_TEMPLATE.md`](templates/AI_USAGE_LOG_TEMPLATE.md) 区分人类输入、AI 输出、采用/拒绝。
- [ ] 使用 [`CHILD_CONTRIBUTION_LOG_TEMPLATE.md`](templates/CHILD_CONTRIBUTION_LOG_TEMPLATE.md) 记录原话、证据位置与最终影响。
- [ ] 对外说明只陈述有记录支撑的贡献；缺证据标“待核验”。
