# 团队运行模式

共同原则：孩子做价值判断，制作人承担范围和交付；AI 的作用是扩展、实现和验证，不代替孩子署名。

## 女儿在线

| 角色 | 现场职责 | 证据 |
|---|---|---|
| 芊芊 | 判断规则是否想再玩一次；提出反常识变化 | 原话、草图、选择时间 |
| 萱萱 | 判断画面情绪与角色吸引力 | 原话、草图、选图记录 |
| 制作人 / 主智能体 | 主持、范围、时间、缺陷裁决、拍板 | 决策导出、版本和测试记录 |
| KK3 | 关键决策前给少量只读意见 | 审查摘要 |
| G53 | 实现已批准目标 | 文件、diff、测试结果 |
| MM3 | 里程碑前做限时阻断检查 | 复现、级别、结论范围 |

- [ ] 每个重要取舍只给孩子 2–3 个清楚选项。
- [ ] AI 产出不得改写成孩子原创；孩子改变了什么要记录。

## 女儿卡壳或离线

- [ ] 使用 [`CHILD_CREATIVE_SCRIPT.md`](CHILD_CREATIVE_SCRIPT.md) 的低压力脚本，不连续追问。
- [ ] AI 最多给 3 个明显不同的选项及代价，不替孩子选择。
- [ ] 制作人先推进可逆工程；角色、情绪和记忆画面进入“待孩子判断”。
- [ ] 孩子恢复在线后只补关键价值判断，不要求补做完整策划。

## 记录

- [ ] AI 使用和儿童贡献分开记录。
- [ ] 对外只陈述有证据支持的贡献，其余写“待核验”。
