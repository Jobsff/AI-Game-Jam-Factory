# AI Game Jam 现场作战手册

目标：**30 秒懂玩法，3–5 分钟讲清作品，截止前提交稳定 Demo。** 当前交付模式：`JAM_DEMO`。

## 优先级

1. 核心玩法和主题成立。
2. 开始 → 玩法 → 胜负 → 重来完整。
3. 视觉、音效和操作反馈有完成度。
4. 演示窗口稳定，材料齐全。
5. 商业级架构、长期性能和全面审计赛后处理。

## 角色路由

- 制作人 / 主智能体：范围、时间、缺陷优先级和最终拍板。
- 孩子：玩法趣味、情绪、画面和取舍的真实判断。
- KK3：定题或重大范围决策时调用一次，15 分钟内收敛。
- G53：主要生产者，持续实现和修复已批准问题。
- MM3：只在首次可玩和功能冻结后做限时阻断检查。

## 生产线

```text
60 分钟定题 → 设计冻结 → G53 灰盒闭环
→ MM3 首次可玩检查（20 分钟，最多 5 项）
→ G53 内容与表现打磨 → 功能冻结
→ MM3 最终检查（30–45 分钟）
→ 最多一次阻断返修与原问题回归 → 视频、文档、打包、提交
```

## 缺陷裁决

- P0/P1：必须修复或回退。
- P2：由制作人按主路径、剩余时间和绕行成本决定。
- P3：全部进入赛后 backlog。
- MM3 只报告风险，没有自动排期权；回归不得扩大攻击范围。

## 现场红线

- 可玩闭环出现前，不做装饰性美术和全面审计。
- 功能冻结后，不新增玩法；距提交不足 12 小时不重构，6 小时内只修 P0/P1。
- 美术每 90 分钟按 [`ART_FALLBACK.md`](ART_FALLBACK.md)判断是否降级。
- 孩子不承担夜间生产；AI 和成人的贡献不得记在孩子名下。
- 每次休息和关键节点都保留一个可运行版本。
