# 技术冻结规则

## 冻结对象

制作人锁定以下四项，智能体不得自行改变：

- 核心循环：玩家动作 → 反馈 → 进度/失败 → 重来。
- 输入所有权：谁接收、何时启停、如何清理。
- 状态机：状态、初始值、合法转换和终态。
- 公共契约：事件、payload、数据格式和外部接口。

实现确需改变时，先提交契约冲突，由制作人决定。

## 工作批次

- 先读 `GAME_MAP.md` 和相关模块契约，再改代码。
- 一个批次只解决一个目标；文件范围由任务包给出。
- G53 是默认唯一写入者；KK3/MM3 默认只读。
- 先复现再修，运行与当前交付模式相称的验证。

## JAM_DEMO 冻结后

- 只接受 P0/P1，以及制作人明确批准的 P2。
- 不新增玩法、不更换架构、不引入重型依赖。
- MM3 最终检查后只允许一次返修；回归只验证原问题。
- P3、长期性能治理和商业化重构进入赛后 backlog。

通用规则见 [`MULTI_AGENT_WORKFLOW.md`](MULTI_AGENT_WORKFLOW.md)。
