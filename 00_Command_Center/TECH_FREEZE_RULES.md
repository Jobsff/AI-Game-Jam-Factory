# 技术冻结规则

## 人类锁死区

- [ ] 核心循环：玩家动作 → 游戏反馈 → 进度/失败 → 重来。
- [ ] 输入：pointer/keyboard/touch 的唯一所有者与启停时机。
- [ ] 状态：合法状态、初始状态、转换条件。
- [ ] 事件：名称、payload、发出者、订阅者、清理责任。

Codex 不得自行改动以上四项；如实现需要变更，先提交契约冲突报告。

## 三层地图与工作批次

1. 体验地图：Scene、UI、玩家可见反馈。
2. 运行地图：状态机、事件流、生命周期。
3. 实现地图：模块、prefab、数据、资产。

- [ ] 先更新 `GAME_MAP.md`，再写代码。
- [ ] 一次只做一个模块、最多 3 个文件；测试文件计入 3 个。
- [ ] 先填 `MODULE_CONTRACT.md` 再实现；集成另开一轮。
- [ ] 先复现再修，修后跑相关测试和完整测试。
- [ ] 冻结后只接受缺陷修复、可访问性或交付阻断；新增玩法进入赛后 backlog。
